# Memory

## What To Store

Store observed thinking patterns, not transcripts.

Track:

- strengths
- recurring risks
- current focus
- case families recently used
- useful corrections
- skill changes with reasons
- next recommended practice

## Evidence Rule

Every durable memory should come from an observed answer, session artifact, or user-provided fact.

Use cautious language:

- "often"
- "in this session"
- "tends to"
- "showed improvement in"
- "needs another observation before changing score"

Avoid permanent labels.

## State Files

Use `state/user_thinking_profile.md` for durable thinking patterns.

Use `state/skill_matrix.md` for current skill estimates.

Use `state/session_log.md` for dated session notes and score-change reasons.

When the user asks to forget, remove or revise the relevant state directly.
